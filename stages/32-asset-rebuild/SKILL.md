# 阶段 3.2：素材重建

**停机点：无。** 素材重建做完直接进入 3.3，不得中途结束任务进程。

**开工前先读规范库**：先读[执行与验收约定](../../shared/operations.md)的《规范库索引（按步骤）》里「3.2 素材重建」一行与它列出的章节，再读[共享工件约定](../../shared/artifact-contract.md)的对应小节；每进入一个新步骤都重读该步骤的章节，不要凭记忆。

前提是 `05_reconstruction/element-inventory.md` 与 `05_reconstruction/slide-elements.md` 已完成。将加工素材分别放入 `05_reconstruction/photos`、`vectors`、`rasters` 和 `cutouts`，不修改原始材料。这里准备装饰、图形、图标、图表、局部抠图和非计划图片所需素材；`image-plan.json` 规定的图片继续保留原计划路径和位置，等阶段 3.3 插入，不能在本阶段改变计划图片区域或提前扁平化进整页背景。

**背景层先铺 AI 大图**：每个页面先放该页对应的大图作背景——标题页 `hero-image`、目录页 `toc-image`、其余页（含致谢页）`content-background`（整页 `image` + `transparency` 与预览一致），再在它上面重建其余元素；**禁止用 AI 整页预览当底图拼接**。**完全拆解元素**：所有可见元素逐个独立重建（原生图形／SVG／抠图），不得把整页预览贴成一张图、也不得在预览图上叠文字或局部补丁；装饰色块与线条一个都不能漏。**渐变风格必须还原**：标题、线条与色块上的渐变（`linearGradient`／`radialGradient`）要记录色标与方向，用阶段 3.2 的 SVG 重绘或按几何还原；不得简化成纯色，除非在 `qa-review.json` 记为已批准偏差。已批准预览只作元素来源，**不能整页拼进 PPTX**。

**异形文本框与线条装饰必须逐一还原，不得省略**：预览里的每个异形文本框（胶囊形、圆角矩形、直角五边形、梯形、六边形、椭圆、气泡、分色色块）和每条线条／点状装饰（托线、线阵、点阵、圆弧、圆环、四芒星、斜向分色）都要在本阶段落实成原生图形或素材。原生形状对不上时按下面的顺序换方法，而不是删掉它；文字仍用原生文本重建，**框内文字要居中**（`align: "center"` ＋ `valign: "middle"`）且不能出框。

## 逐个还原（不得遗漏、不得简化）

以 `05_reconstruction/element-inventory.md` 为清单，对文档里列出的元素**逐个**还原，并保证还原后的形状、配色、渐变、线宽与整体视觉效果与已批准预览一致：

- **形状或颜色复杂**（有机形状、复杂纹样、渐变、光影、材质、难以稳定重绘的装饰）→ 用 **AI 抠图**（局部透明 PNG）或 **SVG 重绘**；
- **形状与颜色简单**（规则几何、纯色块、直线、简单箭头、点阵网格）→ 用 **PPT 原生元素组装**（原生形状／线条／文本框）；
- 两种方式都做不出来时才考虑必要的独立生成位图，并且必须保持同一套视觉语言，不得用近似图形顶替、不得省略、不得简化成普通矩形或纯色。

## 实现优先级

1. 矩形、圆、椭圆、胶囊形、气泡形、直线、简单箭头、分隔线和简单流程图使用 PowerPoint 原生图形；气泡形的高光用叠加的半透明椭圆表达。
2. 可兼顾准确性和可编辑性时，采用原生表格与图表。
3. 扁平图标、已有标识矢量素材、线稿和复杂平面装饰优先使用有效 `viewBox` 的 SVG 重绘；AI 素材显得生硬、边缘发虚或与整套图形语言不一致时，按同一视觉语言重绘为矢量元素，而不是继续叠加位图。
4. 已批准预览中的复杂非文字装饰、纹理或难以稳定重绘的平面图形，可以裁为独立透明 PNG 局部抠图；不得抠取文字、表格、图表、页码或计划图片区域，不得整页抠图。
5. `image-plan.json` 规定的事实图片始终使用登记原件和计划路径，不用 SVG 或生成图替代。
6. 只有在前述方式均不适合时才使用必要的独立生成位图，且必须是非事实装饰、纹理或抽象背景。位图确实需要保留但配色或形态不协调时，可用 `edit_source` 生图编辑后重新登记为新的 `GEN-###`，或重绘为 `RECON-###` 矢量。

用户提供的原照片可以按已批准预览取景裁切以突出主体、统一主体尺度：记录裁剪框、焦点和被保留的主体部位，交给构建器用登记原件裁剪，不修改原件，不裁掉主体关键部位，也不拉伸。

预览中做过 `cutout` 或几何遮罩的 AI 素材必须烘焙成透明 PNG，否则 PPTX 里会出现方形素材：

```powershell
python <skill>/shared/scripts/cutout_asset.py <project> `
  04_full-preview/assets/GEN-104.png 05_reconstruction/rasters/gen-104.png `
  --source-id RECON-010 --source-asset-id GEN-104 `
  --manifest 05_reconstruction/assets.json --description "按已批准预览抠出素材边缘"
```

输出登记 `RECON-###`，记录 `sourceAssetId`、抠图参数与 `transparentRatio`。抠图后没有透明像素或几乎整张素材被抹掉时脚本会失败，此时换素材或改用 `--mask`；不能把方形素材直接交给阶段 3.3。不要用多个基本形状拼合复杂图形，预览中若出现这种拼法，按同一视觉语言重绘为单个 SVG 或改用已抠图的 `RECON-###`。

生图模型通常输出位图，不得把 PNG/JPEG 改名或宣称为矢量。仅在高倍查看结果仍清晰准确时采用描摹或手工、程序化重建；保留位图原件及生成记录。用户提供的标识、证书、真实人物、截图和事实证据不得通过生图重新编造。

SVG 必须有有效 `viewBox`，禁止 `script`、`foreignObject`、外部链接和嵌入位图；检查 XML、渲染结果和 PowerPoint 兼容性，不能通过自动重命名把位图冒充 SVG。

局部抠图在 `crop_asset.py` 中优先使用 `--alpha-mode keep` 或 `--alpha-mode mask`；仅有不透明矩形素材时使用 `flatten`。记录源预览哈希、源区域、目标位置、`z`、透明度方式、排除内容和再生条件。矩形裁剪配灰度蒙版不等于任意轮廓分割，复杂物体必须已有可靠蒙版或改用 SVG 重绘。

检查每项素材的尺寸、透明度、裁剪焦点、颜色、边缘质量和来源映射，在元素清单中补齐最终路径、`origin` 与实现说明。对 `image-plan.json` 中的图片，核对计划路径仍可访问、来源编号有效、原图未被修改；如果计划素材尚未就位，阶段 3.3 必须停止而不是用生成图代替。

进入正片的素材写入 `05_reconstruction/assets.json`：计划中的生成素材保留 `GEN-###` 并增加与 1.3 生成清单的关系；SVG、局部抠图和非计划重建位图使用 `RECON-###`。记录路径、SHA-256、来源、哈希和必要的关系说明。原照片引用材料清单中的原件及其编号，由构建器裁剪；不要把修图后的文件冒充原件。当前没有通用的自动任意矢量重建器，SVG 仍需渲染确认。格式见[执行约定](../../shared/operations.md)。

## 完成条件

`element-inventory.md` 里的每一项都有对应的原生对象方案或经过检查的素材路径（不能整项遗漏、不能用近似图形顶替）；SVG、局部抠图和必要位图均以 `origin=reconstruction` 独立使用；没有伪矢量或整页扁平化；来源可追溯；装饰素材与确认预览相符；计划图片仍按 `image-plan.json` 保留给阶段 3.3 从登记原件插入。标记阶段完成，加载[组装与验收子 skill](../33-build/SKILL.md)。

## 分块贴合与框高适配

贴合分界的卡片框体用 PowerPoint 原生形状或独立 SVG 重建，另放原生可编辑文本；不得把文字裁掉或烘焙进框体图片。图片的边缘显示裁切由 boundaryMask 处理，登记来源仍是原件，不用加工图片路径替换计划原件。圆弧或曲线可采样为平滑轮廓点。
