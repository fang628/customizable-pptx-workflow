# 阶段 1.1：材料分类与需求澄清

设计选择与数值判断统一按[设计判断与检查提示](../../shared/design-principles.md)执行；内容逻辑与可读性优先。

**停机点：1.1（需求与材料确认）。** 需求与材料清单整理完后运行 `workflow.py <project> await 1.1 --notes "..."`，把确认清单交给用户；等用户确认后再 `approve requirements` 并 `complete 1.1`。除此之外不得中断。

**开工前先读规范库**：先读[执行与验收约定](../../shared/operations.md)的《规范库索引（按步骤）》里「1.1 需求与材料」一行与它列出的章节，再读[共享工件约定](../../shared/artifact-contract.md)的对应小节；每进入一个新步骤都重读该步骤的章节，不要凭记忆。

阅读[共享工件约定](../../shared/artifact-contract.md)，使用本阶段模板填写 `00_intake/project-brief.md` 和 `01_inventory/material-inventory.md`。

## 按内容分类

- `reports`：报告、申报书、方案、总结、会议记录。
- `papers`：期刊论文、学位论文、会议论文、文献笔记。
- `photos`：必须保持真实内容的纪实或实拍照片。
- `promo`：海报、宣传册、截图、社交媒体图文。
- `brand`：标识、模板、品牌手册、字体、批准使用的图标。
- `data`：电子表格、CSV、问卷数据、图表。
- `other`：暂未理解的材料；可能影响制稿时必须询问。

不要仅按扩展名分类，也不要移动原文件。记录稳定编号、路径、页码或时间位置、内容摘要、候选用途、权威性、使用权与隐私、处理状态。识别冲突版本并确认采用的权威来源。

## 强制需求闸门

进入阶段 1.3 前，澄清会实质影响内容叙事或设计的信息：

- 目的、主题和使用场合，例如社会实践答辩、大创答辩或组会；
- 受众及希望受众作出的回应或决定；
- 使用语言；
- 约定页数或演讲时长；
- 页面比例固定 16:9，告知用户；若外部提交规范与之冲突，先报告冲突，不擅自改变；
- 是否需要目录页；默认需要。需要时第一页固定为标题页，第二页固定为唯一目录页；不需要时全篇不得出现目录页，第二页直接进入内容页；
- 是否需要致谢页；**默认不需要**。需要时全篇恰好一页 `thanks` 放在末页，顶部进度条必须排除它，并写入 `02_design/content.json` 的 `include_thanks`；不需要时全篇不得出现致谢页；
- 是否需要演讲稿；**默认不需要**。需要时在阶段 3.3 完成后生成逐页演讲备注与完整讲稿（阶段 4），结论写入 `02_design/content.json` 的 `include_speaker_script`；
- 是否需要在除标题页和目录页外的每一页上方添加进度条；默认需要，存在致谢页时另排除致谢页。
- 必需章节或评分要求；
- 模板、标识、颜色、字体和保密约束；字体要给出正文族、标题族和粗体字面，并以 `00_intake/font-report.json` 的实际可用性为准，缺失时记录替代方案；
- 截止时间与交付范围；
- 姓名、职务、日期、争议结论、照片内容和使用许可，以及是否允许使用 AI 生成图像。

只询问不能可靠确定的信息。集中提出相关问题，并说明具体材料中的歧义，不让用户重复已经提供的事实。目录页与顶部进度条即使采用默认值，也必须明确告知默认结论并取得用户确认，不能静默省略。把默认值、用户回答、确认原话和日期写入 `00_intake/project-brief.md`。

## AI 生图配置闸门

在材料分类完成后、阶段1.1需求批准前，必须一次性确认以下五项（阶段1.2任何生图调用前配置须已有效）并主动告知费用口径（第 4 项），把用户确认原话和结果写入 `00_intake/ai-image-config.json`：

必须确认：

1. 生图供应商及 API 地址；接口应同时支持文生图和参考图编辑。
2. 用户选择的具体模型及精确模型 ID。
3. API Key 是否已配置、现有凭据环境变量名称及当前就绪状态。若用户没有指定变量名，由执行者按所选供应商配置合适的变量名，无需让用户决定实现细节。
4. 是否允许向该供应商上传已登记材料作为参考图，以及单次上传上限。
5. 明确告知“会按需多次生成与重试，费用按供应商定价计”，并确认用户理解；不询问每阶段尝试次数预算。

只询问当前尚不清楚的信息，不要求用户填写 JSON、编写脚本或另行安装指定生图 skill，也不向用户展示供应商配置示例。

收到回答后，必须连续完成：

- 复用与用户选择一致的现有凭据配置；需要新增密钥时通过本地隐藏输入或让用户在系统环境变量界面录入，再完成其余配置。不让用户在聊天中发送明文密钥，不回显密钥，也不把密钥写入项目、提示词或 Git 仓库。
- 将用户确认结果与原话写入 `00_intake/ai-image-config.json` 的对应字段及 `notes`；API 地址按调用脚本实际支持的方式配置，不向项目 JSON 添加 schema 不支持的字段。
- 复用、创建或适配所选接口的调用脚本；缺少可用脚本时，在项目的 `00_intake/` 下创建适配器并写入 `adapterScript`，不能停在“请安装另一个 skill”。脚本通过环境变量取密钥，同时支持文生图和参考图编辑；参数及输出遵守 [生图适配器](../../shared/scripts/imagegen_adapter.py) 的 CLI JSON 契约。已有可用的本机配置无需改动。
- 填写所需的 `adapterPython` 和 `adapterArguments`，令模型 ID、API 地址、鉴权、参数及参考图上限与用户选择一致。供应商只由用户选择，不形成指定供应商依赖。
- 用 `check_environment.py --project <project>` 检查环境变量和脚本是否存在，检查 CLI 参数与配置 schema。该检查不调用付费服务，也不证明余额、联网状态或模型权限；不得把未检查的远程能力记成验证成功。
- 凭据就绪必须来自用户确认或实际检查结果，确认后才能设置 `credentialsReady: true`。不得仅修改此标记绕过检查。参考图许可按材料逐项登记，未登记或未获准材料不得上传。

配置完成后，将检查结果连同需求说明交用户一次性确认，再执行阶段 1.1 的批准和完成命令。若仍缺用户必须提供的信息，明确指出缺项并继续可独立完成的配置；不以说明文档代替实际配置。

用户拒绝所有可用生图接口时，记录限制并停止；阶段 2.1／2.2 不得用本地绘图冒充 AI 输出。完成配置后不得静默更换供应商、模型或调用脚本；确需更换时重新确认、更新配置并使受影响的下游批准失效。

## 证据要求

区分事实与解释，保留单位、分母、样本量、时间范围和限制条件。在工件中引用文件名及页码。OCR 识别不确定时明确标记，不擅自猜测。选中的照片须记录主体、裁剪限制、焦点、已知日期地点、必需位置和隐私注意事项。

## 完成条件

用共享 `workflow.py material` 登记原件路径、哈希和上传许可到 `materials.json`。在用户确认需求与 AI 生图配置后，用 `approve requirements --evidence` 记录实际确认，再执行 `complete 1.1`；详见[执行约定](../../shared/operations.md)。材料说明仍写入 Markdown，不把文件哈希当成内容真实性证明。

目录页、致谢页、演讲稿与顶部进度条均已有明确结论并记录用户原话；材料清单与AI配置已确认后完成1.1，继续阶段1.2。
