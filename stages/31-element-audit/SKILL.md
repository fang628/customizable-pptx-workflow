# 阶段 3.1：画面元素拆解

**停机点：无。** 元素清单做完直接进入 3.2，不得中途结束任务进程。

**开工前先读规范库**：先读[执行与验收约定](../../shared/operations.md)的《规范库索引（按步骤）》里「3.1 元素拆解」一行与它列出的章节，再读[共享工件约定](../../shared/artifact-contract.md)的对应小节；每进入一个新步骤都重读该步骤的章节，不要凭记忆。

前提是全部页面预览齐全。**第一步先逐页识别非文字元素**：按本阶段模板编写 `05_reconstruction/element-inventory.md`——逐页列出预览里**除文字之外的所有元素**（**不含计划图片的占位块**；包含全部装饰性线条、线阵、点阵、圆环、圆弧、色块、分色、图形、图标、渐变与光影、材质纹理），写明每个元素的**大致位置**（所在分块／方位＋归一化框）、它服务的文字／文本框／图片，以及**计划的分离方式**（`ai抠图`／`svg重绘`／`原生组装`）：形状或颜色复杂（有机形状、复杂纹样、渐变、光影材质）用前两种，形状与颜色简单（规则几何、纯色、直线、简单箭头）用原生组装，并写一句理由；这份清单是阶段 3.2 逐个还原元素的依据，并同步写出《分离方式汇总》。**第二步**再根据本阶段模板编写 `05_reconstruction/slide-elements.md`，覆盖所有可见元素。`slide-elements.md` 里的每个非文字元素都要能对上 `element-inventory.md` 的某一行，不能有清单外的新元素。

并核对成品实际使用的字体族，避免成品换字面或字号翻倍。

标题与目录文字记录是否使用 `shadow`／`gradient` 及其参数，并写明阶段 3.3 的还原方式：阴影用原生文本阴影；渐变用带 `<linearGradient>` 的 SVG（`RECON-###`）重建，或改用中间色加阴影并把差异记入 `qa-review.json`。

还要记录版面硬约束相关字段：每个元素的 `role`（`content`／`decor`）、随文本的 `textRole`、`overlapWith`，以及 `transform.fontSizeUsed`（`autofit` 后的实际字号，交付磅值取其一半）；文本框的底托与伴衬元素写出编号、覆盖比例与层级关系。内容元素之间的重叠只允许出现在 `overlapWith` 声明过的组合里，其余重叠一律按缺陷处理。

本阶段图片元素不得从占位框反推或重新设计；阶段 3.3 渲染后的成品位置美化按主流程第 28 条另行记录。先从 `02_design/image-plan.json` 继承图片 ID、来源、计划路径、归一化位置、像素位置、`fit`、焦点、裁剪、层级和替代文本。已批准预览里这些位置**就是占位块**（预览不插入真图）：不要照抄占位块的底色、编号或斜叉，也不要把它当成最终画面元素；元素清单继续使用同一组图片编号，并明确“阶段 3.3 从计划路径插入登记原件”。占位块本身的比例必须与计划图片一致（阶段 2.2 已核对）；发现预览里的占位块比例不对，回到阶段 2.2 重新生成并核验批准。

**背景层先铺 AI 大图**：每个页面先放该页对应的大图作背景——标题页 `hero-image`、目录页 `toc-image`、其余页（含致谢页）`content-background`（整页 `image` + `transparency` 与预览一致），再在它上面重建其余元素；**禁止用 AI 整页预览当底图拼接**。**完全拆解元素**：所有可见元素逐个独立重建（原生图形／SVG／抠图），不得把整页预览贴成一张图、也不得在预览图上叠文字或局部补丁；装饰色块与线条一个都不能漏。**渐变风格必须还原**：标题、线条与色块上的渐变（`linearGradient`／`radialGradient`）要记录色标与方向，用阶段 3.2 的 SVG 重绘或按几何还原；不得简化成纯色，除非在 `qa-review.json` 记为已批准偏差。起点是**该页对应的 AI 大图**（标题页 `hero-image`、目录页 `toc-image`、其余页 `content-background`）＋已批准预览："
     "先登记背景层（图编号、插入方式、透明度、是否铺满），再把其余元素逐个拆出来。

**异形文本框与线条装饰一个都不能省略**：胶囊形／圆角矩形／直角五边形／梯形／六边形／椭圆／气泡／分色色块这些异形文本框，以及托线、线阵、点阵、圆弧、圆环、四芒星、斜向分色这些线条／点状装饰，都要逐个记进清单——写清形状、几何、旋转、颜色、粗细、层级与它服务的文本框。原生图形表达不了不是省略的理由，按[重建素材规范](../32-asset-rebuild/SKILL.md)换成 SVG／局部抠图／AI 重画；清单里漏一个，成品就会少一个。同时记录每段文字的对齐方式：**框内文字必须在文本框中心**（`align: "center"` ＋ `valign: "middle"`），并记录字号与文本框尺寸，避免重建时文字偏在一边或出框。

每个非文字元素必须明确采用以下一种实现方式，并在构建规格中保留对应 `origin`：

顶部进度条按可见形态拆成原生对象，不使用整条位图：每个小节一个圆角胶囊段（全圆角矩形），段内一个文本框写该小节标题，文字逐字取自 `content.json` 的 `sections` 并与目录页一致；未到达段、已完成段与当前段记录三种填充色，当前小节标题记录放大后的字号与加粗字重。细线式进度条、省略条内标题或把标题做成图片都算不合格重建。椭圆、胶囊形和气泡形同样用原生形状表达：椭圆用 `ellipse`，胶囊用全圆角 `roundRect`，气泡用椭圆叠加半透明高光椭圆，并记录各自的填充、透明度与层级。

文本框与托线的映射：被色块完全套住的文字，把该色块记为文本框（纯色矩形也算），记录它的形状——胶囊形／圆角矩形／直角五边形／六边形等；同级并列的文本框形状与小元素装饰必须一致，整页不要全是矩形，也不要每个框都用同一种小元素（不同层级换一种装饰语言）。把框内的小圆环／线阵／点阵／圆点／六边形／四芒星／斜向分色记为它的内部装饰：小元素要贴着框边（≤24px）：完全落在框内、压出边界后由 `clip.target` 裁掉出格部分，或把 `opacity` 降到 ≤0.6 压在框上当叠层（不允许直接留在框外），并记录 `clip.target` 指向该文本框；没有文本框的文字，逐条记录托线的 id、方向、粗细与间距，说明它托住哪段文字，并确认相邻托线方向一致、互不重叠。AI 素材记录 `edge` 的插入方式（常规／`cutout`／`feather`）与透明度叠底情况；封面大图的裁剪范围要写明保留比例。

装饰词汇的映射：线条用 `line`，圆弧用 `arc`，圆环用 `donut`（或粗描边 `ellipse`），点阵拆成规则排列的多个 `ellipse`，分色色块拆成 2–5 个相邻 `rect`（斜向分色按同一角度切分），四芒星 `sparkle` 用 `star4`，直角五边形 `right-pentagon`（两直角、一对平行边、上下对称、**锐角朝右**）用 `homePlate`（配构建规格的 `rotate` 90°），V 形 `v-shape` 用 `chevron`，箭头写成 `rightArrow`／`leftArrow`／`upArrow`／`downArrow`；完整的预览图形到预设名对照见[组装与构建](../33-build/SKILL.md)的映射表，写错名字会让阶段 3.3 构建失败；预览的 `rotation` 要在清单里记成构建规格的 `rotate`。逐项记录颜色、粗细、点阵间距、色带占比、位置与层级，并在元素清单里说明该装饰承载的是哪个文本框；圆环线宽要按预览值换算（约内径一半，`RING_STROKE_RATIO`），重建时用同名 `donut` 并记录环孔与线宽比例。小装饰不要游离：与最近内容间距超过 40px 的孤立小元素要么删掉，要么让它贴住文本框、图片或编号底座。

AI 素材元素必须记录边缘处理：预览里的抠图／羽化方式、`cutout` 参数

| 实现方式 | 适用内容 | `origin`／来源 | 重建要求 |
|---|---|---|---|
| 原生文本、形状、表格或图表 | 可编辑文字、规则几何、数据图表 | 不适用 | 使用 PowerPoint 原生对象 |
| SVG 重绘 | 扁平图标、线稿、复杂平面装饰 | `reconstruction`；`RECON-###` 或计划来源说明 | 有效 `viewBox`，不含脚本、外部资源和嵌入位图 |
| 局部抠图 | 已批准预览中的复杂非文字装饰、纹理或不可稳定重绘图形 | `reconstruction`；`RECON-###` | 记录源预览、裁剪框、目标框、层级、透明方式和排除内容 |
| 进度条标题文本 | 顶部进度条每段的标题 | `progress`；文字取自 `content.json` 的 `sections` | 阶段 3.3 重建为独立文本框，标注 `origin: "progress"`，不计入页面文案 |
| 计划图片 | `image-plan.json` 规定的人物、地点、照片、截图等 | `planned`；材料编号或 `GEN-###` | 预览里是原位占位块；阶段 3.3 按 `image-plan.json` 从同一路径插入登记原件 |
| 必要位图 | 无法由原生对象、SVG 或局部抠图忠实重建的独立视觉素材 | `reconstruction`；`RECON-###` | 只限非事实装饰，保留来源和生成说明 |

局部抠图只用于重建装饰、纹理和非文字图形，不得抠取文字、表格、图表、页码或计划图片区域，也不得把整页预览裁成一张图。记录至少包括：源预览路径和哈希、源区域、目标位置、`z`、是否保留透明通道或背景色、明确排除的内容，以及重新生成该抠图所需条件。

计划图片必须在 3.3 按图片计划插入；SVG、局部抠图和非计划重建位图作为独立对象插入，不进入 `image-plan.json`。与确认预览不同之处必须记录，不擅自重新设计。

文字逐项核对 `02_design/content.json`，不要从生成图重新 OCR 后覆盖定稿。元素编号沿用定稿，层级写成整数 `z`；构建器按其排序。归一化坐标分别乘画布宽高后转英寸，记录裁剪的原图焦点。

## 完成条件

`element-inventory.md` 已逐页写全非文字元素（不含占位块）并给出《分离方式汇总》，与 `slide-elements.md` 一一对应；每个可见元素有对应清单记录或明确背景归属；计划图片与 `image-plan.json` 一致且保留阶段 3.3 从登记原件插入的标记；所有照片与事实结论有来源；坐标和层级可执行；实现方式和可编辑性明确。标记阶段完成，加载[素材重建子 skill](../32-asset-rebuild/SKILL.md)。

## 分块贴合与框高适配

识别时记录元素对应的特殊分块、沿弧线或其它边界的排列轨迹、框体与图片被裁切的一侧、轮廓和文字安全区域；框体与文字分开登记，文字完整保留。记录框高与实际文字的适配情况，成品可修正多余框内留白。
