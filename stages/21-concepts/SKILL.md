# 阶段 2.1：三版视觉方向（AI 整页预览）

生图默认通过imagegen内置工具；外部接口仅在用户明确选择时使用。调用与结果登记统一按[生图通道契约](../../shared/image-generation.md)。

职责、底图术语、页型例外、原生文字与返工路由统一见[阶段边界与返工路由](../../shared/artifact-contract.md#阶段边界与返工路由)。

设计选择与数值判断统一按[设计判断与检查提示](../../shared/design-principles.md)执行；内容逻辑与可读性优先。

**停机点：2.1（方案确认）。** 三版代表页生成完后运行 `await 2.1`，把 A/B/C 的对比结论交给用户；用户选定后再 `approve concept --option <x>` 并 `complete 2.1`。

**开工前先读规范库**：先读[执行与验收约定](../../shared/operations.md)的《规范库索引（按步骤）》里「2.1 A/B/C 方案确认」一行与它列出的章节，再读[共享工件约定](../../shared/artifact-contract.md)的对应小节；每进入一个新步骤都重读该步骤的章节，不要凭记忆。

**提示词编写前再读**：每轮编写或修订提示词（含图生图返工）前，按[三个必读时点](../../shared/operations.md#三个必读时点)重新读取当前任务对应规范并核对最新项目工件，读后再写，自检不能替代阅读。

前提：`02_design/design-spec.md` 已经用户复核、`00_intake/ai-image-config.json` 已确认。先读设计稿、`02_design/content.json`、[六种风格与三类页面规范](../13-design/references/style-guide.md)、[实测风格令牌](../13-design/references/style-tokens.json)与[参考版式意图](../13-design/references/layout-intent.md)。

## 原图比例闸门

整页任务size与供应商实际原图都必须是精确16:9（宽×9＝高×16）。请求默认1920x1080，asset_mode使用strict；不符合就退回并保留来源记录，不补边、不裁切修正。合格原图仅等比缩放到1920x1080后再审阅。

## 生图提示词的禁写信息

提示词的Markdown九项结构与嵌套分块树、禁写几何、参考图与返工要求统一见[生图提示词口径](../13-design/references/gen-prompt-scope.md)；本文件只记录当前阶段的操作。

## 预览图由 AI 直接生成

- 三版预览图就是**AI 生成的整页设计图**（精确 1920×1080），不再用本地基本图形拼页面。
- 每页一条生图任务：任务写进 `03_concepts/generation-jobs.json`，真实调用记录写进 `generation-ledger.json`；规范化输出固定为 `03_concepts/assets/GEN-###.png`，再把同一张图放到对应方案的 `03_concepts/option-<x>/<Sxx>.png`。
- **没有骨架图中转稿**：每一页都直接按设计稿生成。封面和目录给「该方向原底图（`hero-image`／`toc-image`）＋单页设计稿」，在原底图上构建，不画图片占位框，按[原底图构建契约](../../shared/preview-contract.md#封面与目录的原底图构建)；不提供分块示意图；可放已获准的旧稿代表页或已生成的同类预览作风格参考。分区及全部文本框、其他图形元素由提示词详细说明。
- 不运行分块参考复制作为预览前置步骤，不把分块参考图加入 references；提示词提取、同一套配色、占位图与上传要求统一见[生图提示词口径](../13-design/references/gen-prompt-scope.md)，promptSummary 记录实际采用的设计信息。
- 先dry-run自检任务和提示词，再按通道契约调用工具并登记；机检项目见生图提示词口径，不在此重复。
- 提示词登记：本阶段所有生图任务的提示词都要写进 `02_design/generation-prompts.md` 的「## 阶段 2.1」小节（逐任务写 id、素材编号、用途、参考图（风格参考、获准材料或返工原页）与提示词全文）。
- 生成后逐页登记 `03_concepts/option-<x>/preview.json`（结构见 `shared/schemas/preview-pages.schema.json`）：`id`、`file`、`jobId`、`sha256`、`promptSummary`（除封面／目录外的计划图片页还要写 `placeholders`），可补 `iterations`、`review`。`complete 2.1` 会逐条核对：文件存在且为 1920×1080、阶段 2.1 的预览哈希／阶段 2.2 的 AI 原始页哈希与账本一致、任务元数据绑定页面，提示词不写内部任务页面绑定与分块方式／形态、文字的语义角色、逐张图片位比例、占位块位置与比例与图片计划一致（占位框换算的宽高比与登记原件默认相对偏差容差为 12%；多次修订后的有限放宽见比例契约）。

```powershell
python <skill>/stages/21-concepts/scripts/run_generation.py <project> --stage concepts
# 仅用户明确选择并配置外部CLI通道后执行；默认内置模式见生图通道契约
python <skill>/stages/21-concepts/scripts/run_generation.py <project> --stage concepts --execute
```

先dry-run检查任务，再按通道契约调用内置工具并登记结果；`--execute`仅用于已确认的外部CLI。生图不设次数预算：效果不理想就用 `edit_source` 生图编辑、改提示词重生成或追加候选，淘汰的候选同样保留登记与原因。除下文多轮失败后的本地空白图框修正外，被退回或需要修改的整页预览用图生图改原图：把被退回的那张图放进任务的 `references`（或用 `edit_source` 指向本地 `GEN-###`），提示词写明保留什么、改什么，在该图基础上重绘；不得重新文生图从头生成。

## 视觉基准与构图比较

先读取设计稿《视觉基准》。用户认可的旧稿代表页在登记并获准上传后，可与基础主题图一起作为风格参考，遵守上传上限；分块示意仅在本地研究，不加入生图references，实际分区由提示词详细描述。参考数量不足时优先保留最能传达本页目标的参考，不擅自上传未授权材料。三方向可以采用不同的排版风格，包括不同的宏观分块、图文布局、阅读路径、文本框组织和特殊分块组合；三方向保持事实内容、文案、材料身份与核心叙事关系一致，不要求沿用同一套版式或分块。不同布局应服务各自视觉方向，不能改变内容逻辑，也不能为了制造差异而牺牲可读性；不固定用三张卡片承载所有代表页。

## 代表页范围

默认每版三张：同一标题页、同一内容页，以及用户确认需要目录时的一张目录页。**内容页任选一页，不限定第一页**——优先挑信息量最大、版式最复杂的一页；`complete 2.1` 只要求「至少有一页内容页代表页」。`content.json` 的 `include_toc` 为 `false` 时不得凭旧模板补目录页，改用另一张代表性内容页。代表页数量不足时优先保留标题页和一张复杂内容页。

同一代表页在三版中保持**文案与材料身份一致**，比较整体设计方向；版式可以不同，不把“只比较设计”理解为必须复用相同分块。标题页不得出现进度条；存在目录页时目录页不得出现进度条；其余合格内容页必须在顶部包含且只包含一条粗分段进度条：条内逐段写出 `content.json` 的 `sections` 全部小节标题（与目录页逐字一致），当前小节标题放大或加粗，当前分段与整条、与已完成分段有色差。

## 提示词口径

按[生图提示词口径](../13-design/references/gen-prompt-scope.md)编写Markdown九项列表及嵌套分块树，文案和事实身份在三方向间一致。参考图只提供视觉语言，素材采用和背景选择以设计稿为准。

## 信息密度与文字配色落实

三方向按[信息密度、逻辑与配色建议](../../shared/content-density-and-text-color.md)保留充分文案与真实逻辑；配色可用于表达风格差异，黑白文字与红黄强调仅作建议。提示词描述实际选择的文字颜色与强调；逐页审阅核对密度、层级、阅读顺序及颜色对比与可读性，不按推荐色判定通过。

## 逐页看图与回调

生成不是一次通过。每轮生成后必须逐页实际打开图像检查（不只看脚本返回的路径），逐页核对：文字是否排进框位、字号与留白是否匹配、排版重心与对齐是否合理、元素组合是否和谐而不僵硬、是否堆砌杂乱、是否贴合主题、是否有专业学术感、进度条是否合规。

逐页看图时要核对文本框是否落实：设计稿指定的形状要点得出、**框底填充色与页面底色有适度色差、反差柔和；不以描边代替**、同级并列的文本框基础形状与颜色要一致，高度按文本适配，局部裁切轮廓可随分界变化、写明「无文本框」的段落不能凭空套框；另外**目测**其他页型的每个图片占位块的宽高比是否与计划插入的原件比例一致（这是看图时的粗略检查、不是机检：`complete` 只核对清单声明的框与计划、原件比例是否在容差内，画面实际框位与比例仍须逐页看图确认）；明显不一致就用图生图重画占位块，或修正清单里的占位框后复看。**目录页的每个条目都要有标号**（编号落在编号底座上）。每一页生成后都要与设计稿对一次：分块方式与走向、每个元素的位置与大小、文字与图片位是否与设计稿一致；弧线／斜线有没有被拉直；明显偏离就按设计稿重新生成该页。发现问题就回调：**退回修改走图生图**——被退回的那张图进 `references`（或用 `edit_source` 做生图编辑：局部重绘、换配色、换装饰），提示词逐条写明保留项与调整要求；也可补生成候选或用 `crop_asset.py`／`cutout_asset.py` 调整构图，但不得用文生图重画一张新的。每轮的问题与调整写进 `preview.json` 的 `review` 与 `03_concepts/concept-review.md`，直到三版逐页达标再交给用户。

## 方案闸门

三版分别存入 `03_concepts/option-a`、`option-b`、`option-c`。把通道、模型路由、真实调用编号、提示词哈希、原始／规范化输出哈希、种子、采用或淘汰的 `GEN-###`、`edit_source` 编辑关系写入 `03_concepts/prompts/` 与 `generation-ledger.json`。

填写 `03_concepts/concept-review.md`：各方案的气质、视觉系统、结构图形语汇、生成与挑选过程、优点、风险、照片保真与预计可编辑程度。向用户展示三版全部代表页并询问选择或修改意见，状态置为 `awaiting_user`；在用户明确确认前不得生成整套预览。确认后用 `workflow.py approve concept --option <a|b|c> --evidence "实际确认记录"` 记录，再 `complete 2.1`，加载[完整预览子 skill](../22-full-preview/SKILL.md)。不得伪造确认。

## 分块贴合与框高适配

按[设计判断与检查提示](../../shared/design-principles.md)选择是否贴合分界及卡片是否等高；具体关系写在单页设计稿，提示词提取按 gen-prompt-scope.md。裁切轮廓在图片计划和重建规格中记录，原生文字与事实信息保持完整。

## 背景与文本框底色协调

底色层级与文字可读性按[设计判断与检查提示](../../shared/design-principles.md)；本项目分别记录填充色、描边色和实际采用的对比关系。

逐页实看还须核对[每页配图与并列文字拆分要求](../../shared/design-principles.md)：每页都有内容相关配图，多段并列文字各有独立文本框；发现缺图或合并大文本框时修订后复看。

占位框经过多次实际修订仍有小幅比例偏差时，执行[有限放宽规则](../../shared/preview-contract.md#多次比例修订后的有限放宽)：默认 12%，至少两轮修订并实际看图、记录 aspectReview 后可放宽至 15%；不为可接受的小幅偏差反复生图，原图等比、信息完整与可读性要求仍须满足。


同一图片位多轮比例修订仍无效时，允许[本地修正空白图框](../../shared/preview-contract.md#多次修订后的本地空白图框修正)，不再为框比例反复生图；保留原页与账本，修正后同步实际框位、插图并逐页复看。
