# 阶段 1.3：逐页设计稿

生图默认通过imagegen内置工具；外部接口仅在用户明确选择时使用。调用与结果登记统一按[生图通道契约](../../shared/image-generation.md)。

职责、底图术语、页型例外、原生文字与返工路由统一见[阶段边界与返工路由](../../shared/artifact-contract.md#阶段边界与返工路由)。

设计选择与数值判断统一按[设计判断与检查提示](../../shared/design-principles.md)执行；内容逻辑与可读性优先。

**停机点：1.3（设计稿复核）。** 设计稿写完后先 `await 1.3`，把设计稿路径与复核要点交给用户；用户回复后同步 JSON、记录原话，再 `complete 1.3`。

**开工前先读规范库**：先读[执行与验收约定](../../shared/operations.md)的《规范库索引（按步骤）》里「1.3 设计稿与复核」一行与它列出的章节，再读[共享工件约定](../../shared/artifact-contract.md)的对应小节；每进入一个新步骤都重读该步骤的章节，不要凭记忆。

**写稿前再读**：每轮开始编写或修订设计稿前，按[三个必读时点](../../shared/operations.md#三个必读时点)重新读取本阶段要求、设计稿模板和本轮对应设计规范，并核对最新需求与已有稿件；不以阶段开始时读过或后续自检通过代替。

复核通过后进入阶段 2.1：**没有骨架图中转稿**，直接用 AI 按本设计稿逐页生成整页预览（每种风格各 1–3 页代表页），不提供分块参考图；分区形态及全部文本框、图形元素通过[详细提示词](references/gen-prompt-scope.md)说明。用户可以**直接修改** `02_design/design-spec.md`；改动会让已完成的 1.3 失效，必须重新 `await 1.3`／`complete 1.3`——**在用户改完并确认之前，不得生成任何整页预览。**

前提是阶段1.2已完成，需求与材料已确认，content-plan.md、图片意图与三方向候选素材及证据齐全。根据本阶段模板编写 `02_design/design-spec.md`。本阶段确定叙事、最终文案、页面类型、分块版式、素材用途、每段文字的字号，以及文字与图片的大致位置和相对大小；不记录坐标、像素框或精确宽高。整页预览按分区与阅读关系生成，实际几何在阶段2.2图片计划与阶段3元素重建中记录。1.3记录框形、配色、装饰与字号的意图或候选；2.1／2.2在已确认意图内完成视觉效果，不自行改变定稿文案、素材身份或内容关系。设计稿导出Markdown后暂停，等待用户复核或修改。

开始实质写稿前，必须已有阶段1.2完成的content-plan.md及《文案与材料原文索引》。从清单选用或精简候选文案，沿用稳定文案编号和来源关系，不从空白设计稿倒推content plan。设计稿中的来源只引用该索引，不重复摘录整段原文；定稿后把材料ID、定位和支撑原文继承到claim-map.json的sourceIds、pages／evidence及对应elementIds，供事实主张核对。发生文字合并、拆分或页码调整时，记录最终文字ID与候选文案编号的映射；新增材料依据先补清单与索引，再更新设计稿和定稿文案。

设计稿要把阶段 1.1 确认的页面要求（是否需要目录页、是否需要致谢页、是否需要演讲稿、顶部进度条）写成独立章节，再写两节设计要求：《文本框、要点拆分与装饰色系要求》《背景底图与内容页补图要求》；缺任一节 `complete 1.3` 会被拒。此外逐页写清分块、最终文字与元素位置和大小。不需要写其他规范条文——它们既不进设计稿，也不进生成提示词。

## 生图提示词

本阶段只写设计稿，不拼接整份规范到提示词；后续生成按[生图提示词口径](references/gen-prompt-scope.md)提取该页内容。

设计稿排版树内的每段最终文案用 Markdown `**文案**` 加粗，角色与样式说明不包入其中；该标记只提高设计稿可读性，不进入content.json，不作为成品字重要求。具体格式见模板的《嵌套排版树写法》。

## 信息密度、逻辑与文字配色

按[信息密度、逻辑与配色建议](../../shared/content-density-and-text-color.md)增加有依据的有效信息，保留必要条件、比较口径、证据、结果及解释。每页写明页内逻辑、阅读顺序和最终文案；不用固定三段模板。文字颜色按主题与层级选择，黑白主色与红黄强调仅作建议；记录实际采用的主色、强调文字ID、短片段与颜色。字号和大致位置写入设计稿，不写坐标。

## 必需内容

并列文本框可按[设计判断与检查提示](../../shared/design-principles.md)采用“小标题＋正文”结构。采用时在嵌套排版树的文字对象中写清每个框的小标题及对应正文，分别标注语义层级并同步到 `content.json` 的 `texts`；逐框小标题为可选项；多段并列文字必须另有统领整组的小标题，已有标题确实概括整组时复用，并登记为定稿文字，不要求AI自行补写。

分块中需要上屏的小标题在嵌套排版树中作为独立文字对象记录一次，标注文字ID与section角色并同步content.json；不再要求在分块同一行重复文案。逐页使用模板的四项结构，布局与文案统一写入树，共用风格集中写入全篇视觉约定。

逐页规划按[设计稿模板](assets/design-spec.md)填写四项：页面信息、页面目的与阅读逻辑、嵌套排版树、本页视觉差异与特殊说明。每段最终文字在树的所属分块内记录一次，并关联文字ID、角色、位置和文本关系；图片和装饰归入实际所属分块。并列段落拆成独立对象，不合并大文本框；需要图注的图片将图注作为对应图片下的独立文字；封面／目录AI底图不新增图注。来源和路径引用图片意图总表及JSON，不逐页抄表。文本框形状、填充、描边、配色与角色字号在全篇视觉约定的风格要求中集中记录一次，局部样式差异写在逐页第四项；特殊分块在风格要求概括造型语言，在树中交代实际形态、组合和归属，轮廓与曲率等允许合理创意发挥，逐页仅写差异。不再单列重复的上屏文案、文字层级、粗略版式和元素位置清单。content.json与最终PPTX文案仍逐字一致，精确几何仍留到阶段2.2和阶段3。旧字段结构继续兼容，新稿采用嵌套树；实际完整性需对照材料与逐页看图检查。逐页不得残留“待填写”。

明确叙事结构，并逐页写明：页码、页面任务、核心结论、准确标题、接近定稿的正文、证据与引用、选用材料编号、标题／目录／内容页类型、结构版式编号、粗略区域关系、素材用途、相对大小、占位标签和可编辑性目标。同时单列《全篇叙述逻辑链》一节：逐页写清这一页承接上一页的哪条结论、要回答或证明什么、把什么结论交给下一页，全篇形成因果与递进链条（不能只罗列章节名）；`complete 1.3` 会核对这一节存在。

同时按用户确认结论划定小节（`sections`）：每个小节的标题与将出现在目录页的条目逐字一致，并覆盖除标题页和目录页外的全部合格页面。小节的标题是顶部进度条条内文字的唯一来源，进度条会在每页重复写出全部小节标题并突出当前小节，因此标题要短、可读、彼此不重复。

封面规划主视觉与标题阅读关系；素材采用、构图、边缘处理和背景选择按[设计判断与检查提示](../../shared/design-principles.md)，写明本项目实际选择。候选素材不自动进入正片。

逐页还要写清每块文字的 `textRole`（提供字号参考）与它的承载方式：无框直接排布，或按阅读需要使用色块／卡片底、图标、编号块等；同一页的内容元素（文本、计划图片、进度条）之间不得重叠，确需重叠要写明 `overlapWith`。字号参考[中文排版与字号规范](references/typography-cjk.md)（正文建议 18 pt／预览 36 px），结合观看距离实际检查可读性，连续空白约达画布 28% 时提示复看；合理留白可保留，按 shared/design-principles.md 判断。

先精简文案，再考虑缩小字号。一页突出一个主要观点；适合时使用结论式标题。所有事实性结论都要能追溯到材料清单。

## 设计阶段补充生成素材

先读取已确认的 `00_intake/ai-image-config.json`，按[生图通道契约](../../shared/image-generation.md)补充非事实性素材：默认使用imagegen内置工具，外部CLI/API仅用户明确选择时使用。就绪状态、参考图许可及上限必须有效；内置工具不要求密钥，也不猜测实际模型。生图按需追加候选，内置按账户额度与使用规则、外部接口按供应商定价说明费用，不静默切换通道。

AI 只负责无文字的视觉素材；准确标题、正文、数字、图表、图例、单位、标识和已有计划图片由本地元素嵌入／排版或阶段 3.3 的原生重建完成。允许生成的类型是 `theme-icon`（贴合主题的简单图标）、`decoration`、`texture`、`abstract-background`、`motif`、`generic-icon`、`illustrative-scene`（具象的说明性现实风格插画）、`hero-image`（封面整体大图）和 `other-nonfactual`。人物、地点、产品、证书、品牌标识、实验装置、显微镜图像、现场照片、截图、图表数据及任何会被理解为证据的内容都必须来自登记材料，不得生图替代；`illustrative-scene` 可以生成，但只能作画面补充，必须标注为“AI 生成示意图”，`factualBoundary` 写明不代表真实人物、地点、事件或数据。生成的素材还要满足[AI 素材的使用尺度](references/style-guide.md)：边缘处理与封面主视觉按内容和阅读需要选择，矩形原边也可保留。生图参考图只能使用已登记且标记 `externalUpload` 的材料；未获上传授权时只进行无参考图的文本生图。不得在日志或项目中保存密钥、签名 URL 或供应商原始敏感响应。

生成前在设计稿“设计阶段补充生成素材”表中写清候选编号、素材类型、用途、页面和大致放置区域、事实边界、参考材料、供应商、模型、提示词摘要和必要时的种子。提示词登记：本阶段（含阶段 1.2 的候选图）所有生图任务的提示词都要写进 `02_design/generation-prompts.md` 的「## 阶段 1.2／1.3」小节（逐任务写 id、素材编号、用途、参考图与提示词全文）。生成后把原始返回图与规范化图存入 `02_design/generated-assets/`，不得覆盖已有文件；实际输出可在该目录下按 `GEN` 编号建立子目录。每项登记到 `02_design/generated-assets.json`，至少包含 `id`、相对 `path`、实际 `sha256`、`kind`、`provider`、`model`、`request_id`（若接口返回）、完整或可复核的 `prompt`、`intendedUse` 和 `factualBoundary`。可补充 `rawPath`、`rawSha256`、`sourceReferences`、`seed`、`createdAt`、`outputSize` 和 `notes`。未被采用的候选也要保留登记和淘汰原因，不能删除证据后复用编号。

生成素材是候选，不会自动进入正片。阶段 2.1／2.2 决定是否把它用作独立装饰或整页预览里的元素；若采用，记录其编号、实际裁切、遮罩或重绘方式以及是否进入最终 PPTX。阶段 1.3 若把生成素材直接作为计划图片写入 `image-intent-plan.json`，必须使用已登记的 `GEN-###` 作为 `sourceId`；除封面／目录的原底图构建例外外，其他页型整页预览里的计划图片**只画占位块**（块内不写内部编号，默认留空或只写简短内容说明，位置与比例按计划），不得生成近似图替代、其他页型2.1概念图不插入登记原件；2.2底稿生成后必须本地插入全部登记原图并逐页检查，再提交批准；缺少事实图片时保留规划并写入《待补充材料》，在 1.3 复核时请用户补充；只有非事实性补充素材可按需要生成或调整版式。其他页型需要占位的图片缺少占位或位置／比例不符合契约时不得批准预览，阶段3.3使用同一登记原件作为独立图片对象组装正式PPTX。局部抠图、SVG 重绘和未被图片计划约束的生成装饰使用 `RECON-###`；进入正片的生成素材必须在阶段 3.2 的 `05_reconstruction/assets.json` 重新登记并保留与 `GEN-###` 的来源关系。

背景、主视觉和补图只记录实际采用项及插入方式；候选按方向登记，操作契约见阶段 1.2，判断依据见 shared/design-principles.md。

标题与目录字号参考 typography-cjk.md，并按观看距离复看；主标题约 36pt、副标题约 24pt、目录条目约 26pt 可作起点；可以给它们加 `shadow`／`gradient` 做立体感（可选，加了要保证可读，并写明交付还原方式）。

图片规划逐页写清（**图片不需要在页面上标注出处**：来源只登记在设计稿《图片意图总表》、材料清单与 `image-intent-plan.json`，页面上不写「图片来源：…」；但**除封面／目录的AI元素底图外，图片旁边必须有图片说明（图注）**，每张图一句，作为上屏文本写进设计稿《图片意图总表》的「图片说明」列与 `content.json` 的 `texts`，编号 `Sxx-CAPTION-01`）：**每页必须有图，全部页型均适用**（照片／数据图／图表／机理图／示意图／主题主视觉都可以），优先用用户直接给的材料（图片文件，或从 PDF 等文件里提取的插图）；缺机理图／示意图时用 AI 生成补充（专业学术风格，生命科学主题尽量贴近 BioRender，不要求和 PPT 同风格）；缺照片、实拍、证书、实验数据图这类事实图片时，在设计稿的《待补充材料》里逐项点名，并在 `await 1.3` 的说明里**主动询问用户补充**（逐项列出页面、材料、用途、格式）；必须的证据缺口要保留登记，按事实与表达需要调整规划，必须的证据缺口保留登记。
分块逐页写清：宏观分块＋分区手法。逐页判断内容关系与阅读顺序；在符合内容逻辑、保持可读性的前提下，使用特殊分块的页面数必须严格大于全篇正式总页数的一半，并尽可能多使用，并写清形态与内容的对应关系。可选斜切、弧线、扇形、同心圆、波浪、金字塔、放射、左圆右栏与蜂窝，适用条件见[特殊分块参考](references/layout-splits.md)。写明形态和内容对应，不把任意弧形背景包装成逻辑分块。横带分块与四宫格分块不算特殊分块；设计稿保留参考库类别名称供统计，实际形态由详细提示词说明，不向生图模型提供分块参考图。
文字承载方式在风格要求中按角色或范围集中写清：哪些文字用色块、哪些无可见框体；封面文案不用文本框。文本框形状由语义与阅读需要决定，同级并列保持一致；全篇使用矩形或圆角矩形也可成立，不强求换形。本页文字之间的逻辑关系（因果／递进／对比／流程）可以写进逐页规划，并在版式里用**箭头**或**箭形色块**表达：写清起止、方向与连接的文字编号，生成整页预览时按设计稿把这套箭头关系画出来（没有逻辑关系就不要乱加箭头）。

装饰与图形只写方向：每页打算用哪些图形词汇（线条、圆弧、圆环、点阵、分色色块等）承载标题／分区／正文块，以及主色与强调色怎么分配；不必写粗细、间距、比例等数值。

## 版式参考

先读取[参考风格与选型规范](references/style-guide.md)、[参考版式意图](references/layout-intent.md)和[参考分类库](references/reference-categories.json)，从六种候选风格（A–F）中按题材推荐主方向和备选方向，把它们落成设计稿里的**三种设计风格（方向 `a`／`b`／`c`）**——与阶段 2.1 的 `option-a/b/c`、阶段 1.2 候选图的 `styleId` 一一对应，逐方向写明理由、色彩语义与装饰词汇，并在[实测风格令牌](references/style-tokens.json)中核对色调、装饰图形、文字风格、装饰图片和排版风格五个维度。文字规划同时读取[中文排版与字号规范](references/typography-cjk.md)，明确字号体系（预览像素与交付磅按 ÷2 换算）、行距、标点与中英混排规则。标题页、目录页、其余内容页分别参考[标题页菜单](references/title-page.md)、[目录页菜单](references/toc-page.md)、[内容页菜单](references/content-page.md)，也可以自行设计。按需查看参考索引和对应联系表。

设计稿必须规划标题页：第一页固定为 `title`。目录页按阶段 1.1 的确认结果处理：需要时第二页为唯一 `toc`；不需要时第二页直接为 `content`，全篇不得出现目录页。其余页面按内容页规划。逐页填写 `page_type`、风格方向、`layout_id`、预备的 `reference_categories` 和 `reference_ids`，并用“左侧／右侧／上方／下方／中央／全幅背景”等词语描述模块的粗略关系，以及哪个区域优先、哪些内容相邻、装饰框大致是什么颜色和形状。

读取[中文参数版式指南](references/layout-guide.md)及其链接的版式资料，只把它们当作结构参考。阶段1.3在风格要求中集中记录角色字号，在嵌套排版树的对应对象下记录文字与图片的位置、对齐与内容关系；不记录坐标、像素框或精确宽高。生图提示词提取分区、相对文字层级与阅读关系，不包含具体字号；精确几何在阶段2.2图片计划和阶段3重建规格中记录。全套画布与预览强制 16:9，标准预览 1920×1080，执行[比例规范](../../shared/preview-contract.md)。

同步建立 `02_design/content.json`，固定页面顺序、准确文案、文本元素 ID、材料引用和 `sections` 小节划分；字段见[执行约定](../../shared/operations.md)。启用进度条时必须提供 `sections`，覆盖全部合格页面且每页只属于一个小节；标题与目录页逐字一致。后续素材生成与整页预览不得自行修改定稿文字或小节标题。

同步建立 `02_design/image-intent-plan.json` 和设计稿中的“图片意图总表”。每一张计划图片必须明确写出：图片 ID、来源或材料 ID、图片内容描述、计划插入路径（已知时）、所属页面、放置区域、与其他模块的关系、相对大小、适配意图、焦点／裁剪意图、层级意图、替代文本、占位标签和使用理由。`description` 必须让人能直接判断要插入哪一张图，不能只写“配图”或复述占位标签。设计稿 Markdown 与 JSON 必须使用同一组编号；图片意图 JSON 和该总表不写精确 `box`、`pixelBox`、最终字号或像素级构图；角色字号集中写入风格要求，逐页嵌套排版树只记录大致位置和相对大小，不写坐标，最终图片计划在阶段 2.2 定稿。

阶段 2.1／2.2 根据设计稿的页面类型、结构版式、放置意图、风格和题材，从分类库选择 1–3 个参考结构，生成独立 `GEN-###` 素材（不设次数预算，可以多出候选），按设计稿及详细元素提示词生成整页预览，并完成精确 `image-plan.json`。其他页型的照片与实验数据图在 AI 页面底稿里只画占位块（块内不写内部编号，默认留空或只写简短内容说明）；阶段 2.2 在批准前本地插入登记原图并逐页检查，阶段 3.3 使用同一原件组装；不得用生成的近似图替代。生成候选只作为独立装饰、纹理或图形参与画面，不能替代事实图片，也不能伪装成整页 AI 输出的成品图。

根据内容组合使用封面、章节过渡、结论加证据、对比、流程或时间线、照片叙事、关键指标、矩阵或框架、引语或证言、总结或行动页。查询与比较数据使用表格，定量关系使用图表。不要全篇重复一种布局。

明确全套的设计方向、信息层级、色彩语义、素材保真边界、原生图形／SVG／图表的职责和章节节奏。主色、字体组合、装饰密度和具体构图在阶段 2.1／2.2 生成整页预览时定稿，设计稿“顶部进度条要求”章节按阶段 1.1 的确认结论写清显示范围、条内全部小节标题、当前小节突出与分段色差。

## 设计稿导出与用户复核暂停

设计稿以人可读的 Markdown 为唯一复核入口，固定导出到 `02_design/design-spec.md`，由用户直接修改。设计稿、`content.json`、`claim-map.json`、`image-intent-plan.json` 和 `generated-assets.json` 全部写完后，先运行：

```powershell
python <skill>/shared/scripts/workflow.py <project> await 1.3 --notes "设计稿待用户复核或修改"
```

然后在对话中给出该文件的绝对路径，说明修改方式（直接编辑文件，或让代理改），并列出建议复核的要点：叙事与章节划分、小节划分与目录条目（进度条条内文字）、逐页准确文案、页面类型与结构版式、图片意图总表与占位标签、素材保真边界、装饰方向。

此时必须停止：不得运行 `complete 1.3`，不得加载[三版方案子 skill](../21-concepts/SKILL.md)，不得开始任何生图。

用户提出继续后，重新读取该文件，逐条与 `content.json`、`claim-map.json` 和 `image-intent-plan.json` 对齐，并遵守：

1. 用户在设计稿中的修改是最高优先级的设计要求，覆盖代理原稿。
2. 用户改动文案、页面顺序、页面编号、图片编号、来源或页面类型时，必须同步更新对应 JSON，不能留下 Markdown 与 JSON 不一致的状态。
3. 用户改动与登记材料事实冲突的数值、结论或来源时，以登记材料为准，向用户说明并请其确认，不得直接写入设计稿或 JSON。
4. 用户的修改不能违反本项目的事实与信息限制（封面信息、材料保真、排除项）。
5. 把用户确认继续的原话与日期记入设计稿“设计状态”的“设计稿复核”一行。

核对完成后，先汇报本轮差异（改了哪些页、哪些文案、哪些图片意图、哪些未采纳及原因），再运行 `complete 1.3` 并加载[三版方案子 skill](../21-concepts/SKILL.md)。阶段 1.3 只有在用户复核结束并给出继续指令后才能完成。

## 完成条件

每页都有文案、证据、页面类型、结构版式、粗略区域关系、图片意图和可编辑性说明；第一页为标题页，目录页条件与阶段 1.1 结论及 `content.json` 一致；`sections` 已定义、覆盖全部合格页面且标题与目录页逐字一致；`image-intent-plan.json` 与设计稿总表一致；每张计划图片明确说明插入内容、来源和大致放置关系；补充生成素材均有用途、事实边界和 `generated-assets.json` 登记；《待补充材料》已逐项点名（没有缺图时写「无」）；页数适合演讲时长；必需的确认结论齐全（目录页／致谢页／演讲稿／进度条），两节设计要求（文本框与要点拆分／背景底图与内容页补图）已写，《全篇叙述逻辑链》已逐页写清承接与递进；不存在会改变设计的未明确需求。设计稿已按《设计稿导出与用户复核暂停》交给用户复核，用户的修改已同步到 JSON 并记录复核原话后，标记阶段完成，加载[三版方案子 skill](../21-concepts/SKILL.md)。

## 内容驱动与视觉基准

每页先确定问题、结论、证据和页内关系，再选分块与文本框。不要固定为三段正文加一张图，不按页码轮换框形。同类证据页可复用结构。设计稿《页面分块要求》逐页写“内容关系与选择依据”；特殊分块说明如何强化逻辑，常规分块说明为何更利于阅读。复核整套设计时，检查是否还有适合采用特殊分块的页面，并检查是否过度依赖斜切、弧线；主动尝试其他特殊分块及变体组合，选择依据见[设计判断与检查提示](../../shared/design-principles.md)。尽可能增加合理使用；确认特殊分块页数严格超过正式总页数的一半，同时保持真实内容关系与可读性；参考图允许灵活调整，不要求照搬几何形态。

有用户认可的旧稿时，在《视觉基准》中提取相对层级、密度、对齐、间距、图文比例、框形用途与导航。注明代表页与来源；获准上传后可作为生图风格参考，不复制旧稿事实。无旧稿时根据题材与受众建立基准。

## 分块贴合与框高适配

按[设计判断与检查提示](../../shared/design-principles.md)选择是否贴合分界及卡片是否等高；具体关系写在单页设计稿，提示词提取按 gen-prompt-scope.md。裁切轮廓在图片计划和重建规格中记录，原生文字与事实信息保持完整。
