# 阶段 1.3：逐页设计稿

**停机点：1.3（设计稿复核）。** 设计稿写完后先 `await 1.3`，把设计稿路径与复核要点交给用户；用户回复后同步 JSON、记录原话，再 `complete 1.3`。

**开工前先读规范库**：先读[执行与验收约定](../../shared/operations.md)的《规范库索引（按步骤）》里「1.3 设计稿与复核」一行与它列出的章节，再读[共享工件约定](../../shared/artifact-contract.md)的对应小节；每进入一个新步骤都重读该步骤的章节，不要凭记忆。

复核通过后进入阶段 2.1：**没有骨架图中转稿**，直接用 AI 按本设计稿逐页生成整页预览（每种风格各 1–3 页代表页），用到特殊分块的页面会把对应的**分块参考图**连同设计提示词一起交给 AI（见[执行与验收约定](../../shared/operations.md)的《阶段 2.1／2.2 分块参考图》）。用户可以**直接修改** `02_design/design-spec.md`；改动会让已完成的 1.3 失效，必须重新 `await 1.3`／`complete 1.3`——**在用户改完并确认之前，不得生成任何整页预览。**

前提是阶段 1.1 已完成。根据本阶段模板编写 `02_design/design-spec.md`。本阶段确定叙事、最终文案、页面类型、分块版式、素材用途，以及**每个元素的位置与大小**（归一化框）——整页预览直接按设计稿生成，没有中间稿，位置与大小只能来自设计稿。最终配色平衡、装饰造型、材质与立体感由阶段 2.1／2.2 在生成整页预览时完成。设计稿写完后固定导出 Markdown 并暂停，等用户复核或修改结束后再继续，见《设计稿导出与用户复核暂停》。

设计稿要把阶段 1.1 确认的页面要求（是否需要目录页、是否需要致谢页、是否需要演讲稿、顶部进度条）写成独立章节，再写两节设计要求：《文本框、要点拆分与装饰色系要求》《背景底图与内容页补图要求》；缺任一节 `complete 1.3` 会被拒。此外逐页写清分块、最终文字与元素位置和大小。不需要写其他规范条文——它们既不进设计稿，也不进生成提示词。
## 生图提示词的禁写信息

阶段 2.1／2.2 的新生成与图生图修订提示词，**禁止写文本框的具体尺寸、字号、元素具体坐标**：不写固定宽高、数值尺寸、字号指令或 x／y、像素位置、归一化坐标。允许并必须说明文本框高度贴合文本、仅保留适量内边距、避免框内大片留白；允许说明顺着分块边界排列或裁切显示边缘。保留分区与阅读顺序、文字内容和语义角色、框形与颜色、图片位比例、风格、导航及逻辑关系。整页画布 16:9（1920×1080）与图片位宽高比继续保留。具体坐标、文本框尺寸、字号和裁切轮廓点只留在本地设计稿、图片计划和重建规格中；不得将含这些信息的原始设计稿全文拼入提示词。

## 必需内容

排版分级里，分块里要在画面上显示的分标题要写在分块**同一行**：`- **左分块**：说明…内容；分标题：（一段文字）`，并把这段文字同步到 `content.json` 的 `texts`（`Sxx-SECTION-01`，层级 `section`）；设计稿没写分标题的分块，预览不许自己加。**两页之间不要用完全一样的特殊分块方式**：同一套组合不要原样重复，换一种分块或把形态差异（方向／倾角／弯曲方向／圆心／波峰／顶点）写进分块方式里；`complete 1.3` 会逐页比对，完全相同的组合会被拒。

逐页规划里必须写明「**文字层级与并列**」：列出本页每段文字的编号与层级（标题／小标题／正文／注释），并列的段落用同一组标记，并写明同级并列用同一种文本框形状；框内装饰可省略，选用时同组保持一致；还必须写明「**元素位置与大小**」：逐段文字与每张图片写出归一化框 `x`／`y`／`w`／`h`（0–1）与叠放顺序。缺任一项 `complete 1.3` 会被拒。逐页规划还必须写出「**上屏文案（最终文字）**」：设计稿里写的文字就是最终上屏内容（`content.json` 与交付 PPTX 逐字一致），生成整页预览时它只用于表达内容与语义角色；排版分级里单段文字、并列文本段落、插入图片要分别写明对应的**文本框形状**（无文本框就写明并说明用线条托住），并列文本段落用同一种形状；最终文字从阶段 1.2 的 `02_design/content-plan.md` 精简定稿。排版分级按[设计稿模板](assets/design-spec.md)的《排版分级写法》逐级写全——分块方式 → 各分块 → 分块上部／下部／左部／右部／分块内 → 并列文本逐条，每段文字或图片都要写明对应的文本框或图像框；一段文本里有并列结构（一是／二是、首先／其次、分号或数字并列、多句并列短句）就要拆成列表，条内再并列就再降一级（列表套列表），不要写成一大段。逐页规划里不得残留「待填写」。

明确叙事结构，并逐页写明：页码、页面任务、核心结论、准确标题、接近定稿的正文、证据与引用、选用材料编号、标题／目录／内容页类型、结构版式编号、粗略区域关系、素材用途、相对大小、占位标签和可编辑性目标。同时单列《全篇叙述逻辑链》一节：逐页写清这一页承接上一页的哪条结论、要回答或证明什么、把什么结论交给下一页，全篇形成因果与递进链条（不能只罗列章节名）；`complete 1.3` 会核对这一节存在。

同时按用户确认结论划定小节（`sections`）：每个小节的标题与将出现在目录页的条目逐字一致，并覆盖除标题页和目录页外的全部合格页面。小节的标题是顶部进度条条内文字的唯一来源，进度条会在每页重复写出全部小节标题并突出当前小节，因此标题要短、可读、彼此不重复。

封面必须规划一张整体主视觉：由 AI 生成一张贴合主题的大图（占画布不少于 20%，推荐 35%–60%）；登记实拍主图作为计划图片另行安排，不替代本工作流的 hero-image；不得用多张小素材拼封面。**每页只带一张与页面一一对应的基础元素图**：标题页＝标题图（`hero-image`）、目录页＝目录图（`toc-image`）、其他页＝背景图（`content-background`）；内容页可按表达需要补充已登记的主题图标或说明性插画；不为填满留白强制补图，补充素材不得替代事实图片或统一背景，采用后写入设计稿与素材清单。封面与目录页只用对应主图，并写明插入方式（满幅／抠边／羽化／降透明度叠底）。

逐页还要写清每块文字的 `textRole`（决定字号下限）与它的依托方式：更低层的色块／卡片底，或紧邻的图标、编号块、色条、说明性素材；同一页的内容元素（文本、计划图片、进度条）之间不得重叠，确需重叠要写明 `overlapWith`。所有字号必须落在[中文排版与字号规范](references/typography-cjk.md)的下限之上（正文 ≥ 18 pt／预览 36 px），字号过小或元素过少造成的连续空白区不得达到画布的 28%。

先精简文案，再考虑缩小字号。一页突出一个主要观点；适合时使用结论式标题。所有事实性结论都要能追溯到材料清单。

## 设计阶段补充生成素材

先读取 `00_intake/ai-image-config.json`。只有在用户已确认供应商、模型、凭据状态和参考图上传许可后，本阶段才能通过配置的适配脚本调用真实 AI API 补充非事实性素材；生图不设次数预算，鼓励多生成候选再挑，但要按供应商定价向用户估算费用。默认是 gpt-image-2（VSAKURA 的 `vsakura-imagegen` 脚本，不支持 seed）；Qwen、Agnes 等供应商可选；不得假定某个 skill 必然存在。命令、密钥环境变量、输出协议和参考图上限以已确认配置及实际适配脚本为准，不能静默切换供应商、模型或脚本。

AI 只负责无文字的视觉素材；准确标题、正文、数字、图表、图例、单位、标识和已有计划图片由本地元素嵌入／排版或阶段 3.3 的原生重建完成。允许生成的类型是 `theme-icon`（贴合主题的简单图标）、`decoration`、`texture`、`abstract-background`、`motif`、`generic-icon`、`illustrative-scene`（具象的说明性现实风格插画）、`hero-image`（封面整体大图）和 `other-nonfactual`。人物、地点、产品、证书、品牌标识、实验装置、显微镜图像、现场照片、截图、图表数据及任何会被理解为证据的内容都必须来自登记材料，不得生图替代；`illustrative-scene` 可以生成，但只能作画面补充，必须标注为“AI 生成示意图”，`factualBoundary` 写明不代表真实人物、地点、事件或数据。生成的素材还要满足[AI 素材的使用尺度](references/style-guide.md)：非满幅素材必须抠边（`cutout`）或套遮罩，封面要有一张整体大图，不要零碎堆砌。生图参考图只能使用已登记且标记 `externalUpload` 的材料；未获上传授权时只进行无参考图的文本生图。不得在日志或项目中保存密钥、签名 URL 或供应商原始敏感响应。

生成前在设计稿“设计阶段补充生成素材”表中写清候选编号、素材类型、用途、页面和大致放置区域、事实边界、参考材料、供应商、模型、提示词摘要和必要时的种子。提示词登记：本阶段（含阶段 1.2 的候选图）所有生图任务的提示词都要写进 `02_design/generation-prompts.md` 的「## 阶段 1.2／1.3」小节（逐任务写 id、素材编号、用途、参考图与提示词全文）。生成后把原始返回图与规范化图存入 `02_design/generated-assets/`，不得覆盖已有文件；实际输出可在该目录下按 `GEN` 编号建立子目录。每项登记到 `02_design/generated-assets.json`，至少包含 `id`、相对 `path`、实际 `sha256`、`kind`、`provider`、`model`、`request_id`（若接口返回）、完整或可复核的 `prompt`、`intendedUse` 和 `factualBoundary`。可补充 `rawPath`、`rawSha256`、`sourceReferences`、`seed`、`createdAt`、`outputSize` 和 `notes`。未被采用的候选也要保留登记和淘汰原因，不能删除证据后复用编号。

生成素材是候选，不会自动进入正片。阶段 2.1／2.2 决定是否把它用作独立装饰或整页预览里的元素；若采用，记录其编号、实际裁切、遮罩或重绘方式以及是否进入最终 PPTX。阶段 1.3 若把生成素材直接作为计划图片写入 `image-intent-plan.json`，必须使用已登记的 `GEN-###` 作为 `sourceId`；整页预览里计划图片**只画占位块**（块内写编号或一句说明，位置与比例按计划），不得生成近似图替代、也不得提前插入登记原件；缺少事实图片时保留规划并写入《待补充材料》，在 1.3 复核时请用户补充；只有非事实性补充素材可按需要生成或调整版式。占位块缺失或位置／比例不对时不得批准预览，登记原件在阶段 3.3 按同一路径嵌入正式 PPTX。局部抠图、SVG 重绘和未被图片计划约束的生成装饰使用 `RECON-###`；进入正片的生成素材必须在阶段 3.2 的 `05_reconstruction/assets.json` 重新登记并保留与 `GEN-###` 的来源关系。

背景底图另计：`content-background` 只用于内容页与致谢页的整页背景底图，透明度取 0.10–0.35，叠加后全图明暗反差不高于 35%（推荐 10%–22%），内容必须从课题语义提炼并贴合主题，每页至多一张，封面不用它承担主视觉（封面用 `hero-image` 整体大图）。候选图按设计方向成组：`02_design/generated-assets.json` 每张候选图都要写 `styleId`（`a`/`b`/`c`），每个方向至少一张封面大图与一张背景底图；有目录页时每个方向还要有 `toc-image`；致谢页复用 `content-background`，不要求另生成 `thanks-image`，`complete 1.3` 会逐方向核对。

标题与目录文字要大：标题页主标题 ≥72px（36pt）、副标题 ≥48px（24pt），目录页“目录”标题 ≥72px（36pt）、章节条目 ≥52px（26pt）；可以给它们加 `shadow`／`gradient` 做立体感（可选，加了要保证可读，并写明交付还原方式）。

图片规划逐页写清（**图片不需要在页面上标注出处**：来源只登记在设计稿《图片意图总表》、材料清单与 `image-intent-plan.json`，页面上不写「图片来源：…」；但**图片旁边必须有图片说明（图注）**，每张图一句，作为上屏文本写进设计稿《图片意图总表》的「图片说明」列与 `content.json` 的 `texts`，编号 `Sxx-CAPTION-01`）：**尽量保证每一页都有图片**（照片／数据图／图表／机理图／示意图都可以），优先用用户直接给的材料（图片文件，或从 PDF 等文件里提取的插图）；缺机理图／示意图时用 AI 生成补充（专业学术风格，生命科学主题尽量贴近 BioRender，不要求和 PPT 同风格）；缺照片、实拍、证书、实验数据图这类事实图片时，在设计稿的《待补充材料》里逐项点名，并在 `await 1.3` 的说明里**主动询问用户补充**（逐项列出页面、材料、用途、格式）；材料不齐也要**保留设计稿规划**，不要因缺图改版式。
分块逐页写清：宏观分块＋分区手法——**鼓励使用[分块参考](references/layout-splits.md)里的 9 种特殊分块：斜切／弧线／扇形／同心圆／波浪形／金字塔形／圆形放射／左圆右栏／六边形（蜂窝）**（一套 PPT 一半以上的正文页要用特殊分块，**内容合适时越多越好**；封面、目录页不计入；`complete 1.3` 会统计，严格多于一半才通过），并写明分界的方向、走向、弯曲程度、顶点或圆心位置。**横带分块与四宫格分块不算特殊分块、不计入这个比例，但仍要给出分块参考图**。**特殊分块要用[特殊分块参考](references/layout-splits.md)表里的名称**：写了表外的名字（自造名或拼写偏差）会匹配不到分块参考图，阶段 2.1／2.2 不会给该页参考图。
文字承载方式逐页写清：哪段文字用色块套住（该色块即文本框）、哪段不套框直接用文字排布；封面文案不用文本框。文本框形状要多样：**避免整页／全篇都是圆角矩形**——同级并列用同一种形状，不同层级或不同分块换形状（胶囊、直角五边形、梯形、六边形、椭圆、气泡、分色色块等），防止画面单调。本页文字之间的逻辑关系（因果／递进／对比／流程）可以写进逐页规划，并在版式里用**箭头**或**箭形色块**表达：写清起止、方向与连接的文字编号，生成整页预览时按设计稿把这套箭头关系画出来（没有逻辑关系就不要乱加箭头）。

装饰与图形只写方向：每页打算用哪些图形词汇（线条、圆弧、圆环、点阵、分色色块等）承载标题／分区／正文块，以及主色与强调色怎么分配；不必写粗细、间距、比例等数值。

## 版式参考

先读取[参考风格与选型规范](references/style-guide.md)、[参考版式意图](references/layout-intent.md)和[参考分类库](references/reference-categories.json)，从六种候选风格（A–F）中按题材推荐主方向和备选方向，把它们落成设计稿里的**三种设计风格（方向 `a`／`b`／`c`）**——与阶段 2.1 的 `option-a/b/c`、阶段 1.2 候选图的 `styleId` 一一对应，逐方向写明理由、色彩语义与装饰词汇，并在[实测风格令牌](references/style-tokens.json)中核对色调、装饰图形、文字风格、装饰图片和排版风格五个维度。文字规划同时读取[中文排版与字号规范](references/typography-cjk.md)，明确字号体系（预览像素与交付磅按 ÷2 换算）、行距、标点与中英混排规则。标题页、目录页、其余内容页分别参考[标题页菜单](references/title-page.md)、[目录页菜单](references/toc-page.md)、[内容页菜单](references/content-page.md)，也可以自行设计。按需查看参考索引和对应联系表。

设计稿必须规划标题页：第一页固定为 `title`。目录页按阶段 1.1 的确认结果处理：需要时第二页为唯一 `toc`；不需要时第二页直接为 `content`，全篇不得出现目录页。其余页面按内容页规划。逐页填写 `page_type`、风格方向、`layout_id`、预备的 `reference_categories` 和 `reference_ids`，并用“左侧／右侧／上方／下方／中央／全幅背景”等词语描述模块的粗略关系，以及哪个区域优先、哪些内容相邻、装饰框大致是什么颜色和形状。

读取[中文参数版式指南](references/layout-guide.md)及其链接的版式资料，只把它们当作结构参考。阶段 1.3 不写归一化坐标、像素框、最终字号或精确对齐，也不规定装饰轮廓的像素值。全套画布与预览强制 16:9，标准预览 1920×1080，执行[比例规范](../../shared/preview-contract.md)。

同步建立 `02_design/content.json`，固定页面顺序、准确文案、文本元素 ID、材料引用和 `sections` 小节划分；字段见[执行约定](../../shared/operations.md)。启用进度条时必须提供 `sections`，覆盖全部合格页面且每页只属于一个小节；标题与目录页逐字一致。后续素材生成与整页预览不得自行修改定稿文字或小节标题。

同步建立 `02_design/image-intent-plan.json` 和设计稿中的“图片意图总表”。每一张计划图片必须明确写出：图片 ID、来源或材料 ID、图片内容描述、计划插入路径（已知时）、所属页面、放置区域、与其他模块的关系、相对大小、适配意图、焦点／裁剪意图、层级意图、替代文本、占位标签和使用理由。`description` 必须让人能直接判断要插入哪一张图，不能只写“配图”或复述占位标签。设计稿 Markdown 与 JSON 必须使用同一组编号；图片意图 JSON 和该总表不写精确 `box`、`pixelBox`、最终字号或像素级构图；逐页《元素位置与大小》另行记录本地几何字段，最终图片计划在阶段 2.2 定稿。

阶段 2.1／2.2 根据设计稿的页面类型、结构版式、放置意图、风格和题材，从分类库选择 1–3 个参考结构，生成独立 `GEN-###` 素材（不设次数预算，可以多出候选），参考设计稿与分块参考图生成整页预览，并完成精确 `image-plan.json`。照片与实验数据图在 AI 底稿里只画占位块（块内写编号或一句说明）；阶段 2.2 在批准前本地插入登记原图并逐页检查，阶段 3.3 使用同一原件组装；不得用生成的近似图替代。生成候选只作为独立装饰、纹理或图形参与画面，不能替代事实图片，也不能伪装成整页 AI 输出的成品图。

根据内容组合使用封面、章节过渡、结论加证据、对比、流程或时间线、照片叙事、关键指标、矩阵或框架、引语或证言、总结或行动页。查询与比较数据使用表格，定量关系使用图表。不要全篇重复一种布局。

明确全套的设计方向、信息层级、色彩语义、素材保真边界、原生图形／SVG／图表的职责和章节节奏。主色、字体组合、装饰密度和具体构图在阶段 2.1／2.2 生成整页预览时定稿，设计稿“顶部进度条要求”章节按阶段 1.1 的确认结论写清显示范围、条内全部小节标题、当前小节突出与分段色差。

## 设计稿导出与用户复核暂停

设计稿以人可读的 Markdown 为唯一复核入口，固定导出到 `02_design/design-spec.md`，由用户直接修改。设计稿、`content.json`、`claim-map.json`、`image-intent-plan.json` 和 `generated-assets.json` 全部写完后，先运行：

```powershell
python <skill>/shared/scripts/workflow.py <project> await 1.3 --notes "设计稿待用户复核或修改"
```

然后在对话中给出该文件的绝对路径，说明修改方式（直接编辑文件，或让代理改），并列出建议复核的要点：叙事与章节划分、小节划分与目录条目（进度条条内文字）、逐页准确文案、页面类型与结构版式、图片意图总表与占位标签、素材保真边界、装饰方向。

此时必须停止：不得运行 `complete 1.3`，不得加载[三版方案子 skill](../21-concepts/SKILL.md)，不得开始任何生图。

用户提出继续后，重新读取该文件，逐条与 `content.json`、`claim-map.json` 和 `image-intent-plan.json` 对齐，并遵守：

1. 用户在设计稿中的修改是最高优先级的设计要求，覆盖代理原稿。
2. 用户改动文案、页面顺序、页面编号、图片编号、来源或页面类型时，必须同步更新对应 JSON，不能留下 Markdown 与 JSON 不一致的状态。
3. 用户改动与登记材料事实冲突的数值、结论或来源时，以登记材料为准，向用户说明并请其确认，不得直接写入设计稿或 JSON。
4. 用户的修改不能违反本项目的事实与信息限制（封面信息、材料保真、排除项）。
5. 把用户确认继续的原话与日期记入设计稿“设计状态”的“设计稿复核”一行。

核对完成后，先汇报本轮差异（改了哪些页、哪些文案、哪些图片意图、哪些未采纳及原因），再运行 `complete 1.3` 并加载[三版方案子 skill](../21-concepts/SKILL.md)。阶段 1.3 只有在用户复核结束并给出继续指令后才能完成。

## 完成条件

每页都有文案、证据、页面类型、结构版式、粗略区域关系、图片意图和可编辑性说明；第一页为标题页，目录页条件与阶段 1.1 结论及 `content.json` 一致；`sections` 已定义、覆盖全部合格页面且标题与目录页逐字一致；`image-intent-plan.json` 与设计稿总表一致；每张计划图片明确说明插入内容、来源和大致放置关系；补充生成素材均有用途、事实边界和 `generated-assets.json` 登记；《待补充材料》已逐项点名（没有缺图时写「无」）；页数适合演讲时长；必需的确认结论齐全（目录页／致谢页／演讲稿／进度条），两节设计要求（文本框与要点拆分／背景底图与内容页补图）已写，《全篇叙述逻辑链》已逐页写清承接与递进；不存在会改变设计的未明确需求。设计稿已按《设计稿导出与用户复核暂停》交给用户复核，用户的修改已同步到 JSON 并记录复核原话后，标记阶段完成，加载[三版方案子 skill](../21-concepts/SKILL.md)。

## 分块贴合与框高适配

逐页设计时落实[特殊分块的元素排布](references/layout-splits.md#元素贴合特殊分块)：元素排布必须贴合特殊分块的形态：弧形分块可让文本框的中心或排列轨迹趋近弧线；也可裁切框体靠近分界的一侧，使轮廓贴合弧线、斜线、波浪或扇区边缘。文本本身保持完整、原生可编辑，放在裁切轮廓内的安全区域。图片也可按分块轮廓适当裁切显示边缘，保留关键主体与信息，不改变登记原件或拉伸图片。同级框保持一致的基础形状、配色与内边距；高度随实际文字适配，靠分界一侧的局部裁切轮廓可随边界变化。文本框的高度要与实际文本高度相匹配，仅保留适量内边距，避免框内大片留白；不要为同级等高而把短文本放入过高的框。

## 背景与文本框底色协调

背景色与文本框填充色（框体底色，不是描边色）应有适度色差，能区分层次但避免强烈反差；优先采用协调的邻近色或轻微明度变化。描边色单独说明，不能用边框色差代替填充色差。文字与框底仍须清晰可读。设计和提示词写清填充与背景的柔和层次关系；逐页看图检查实际落地，纹理背景以框所在区域的可见底色为准。
