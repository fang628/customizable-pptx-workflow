# 生图通道与结果登记

本工作流默认使用 `imagegen` skill 的内置 `image_gen` 工具。开工时读取当前安装的该skill（通常在 `~/.codex/skills/.system/imagegen/SKILL.md`），按其内置生成、编辑和保存规则执行；不要复制或修改该skill的脚本。页面提示词仍遵守本工作流的Markdown嵌套排版树与十二项要求，不能因换通道删掉约束。

## 默认配置与就绪

新项目预填 `provider: "imagegen"`、`model: "builtin-auto"`、空 `credentialEnv`／`adapterScript`／`adapterPython`、`credentialsReady: false`、`allowReferenceUpload: false`、`referenceImageLimit: 3`。阶段1.1由代理确认内置工具实际可用，并确认需求和参考图许可后标记就绪；内置工具无需API Key。终端环境检查无法证明内置工具可用，不伪报联网、余额或模型权限已验证。

`builtin-auto`是路由标记，不是实际模型名称；工具未披露模型时不推断或写成gpt-image-2，披露时另记 `tool_model`。默认值只影响新项目，初始化器不覆盖已有项目，已确认外部通道仍继续使用，迁移须明确确认并重新检查下游绑定。

## 内置工具流程

1. 每轮编写提示词前重读本阶段规范与生图提示词口径；把最终实际调用的提示词完整写入任务 `prompt`，输入参考图／编辑源逐项登记。先运行 `run_generation.py <project> --stage content|concepts|full` 自检，不加 `--execute`。终端脚本不代替代理的规范阅读和视觉审查。
2. 由代理逐任务直接调用 `image_gen`，每张素材或变体单独调用。工具参数以当前工具文档为准，不把CLI的model、size、seed、输出路径等当内置工具参数。画布比例写在提示词；本地素材先用 `view_image` 查看，编辑采用原目标图并写明保留项。使用可用的本地路径引用机制；路径机制不可用时按当前工具文档使用已查看的对话图片，不混用两种机制。
3. 上传只包含当前任务登记且获准的输入，并核对数量上限；不上传分块参考图或含事实原件的合成整页。工具生成文件通常保存在Codex默认生成目录；不指定不存在的目标路径参数。取得真实输出后保存调用回执，登记器复制原图到项目raw目录，再生成稳定项目输出；原文件与旧版本不覆盖。
4. 用以下回执登记一张真实工具结果。`tool_result_id`取真实返回文件名，绑定原图哈希；工具披露调用编号时另记`tool_call_id`。没有API request_id、调用编号或实际模型时不编造。工具结果无法保存或核对来源时说明缺项，不把本地绘图登记为工具结果。

```json
{
  "tool": "image_gen",
  "job_id": "本地任务编号，仅用于元数据",
  "tool_result_id": "实际返回原图文件名",
  "source_file": "工具实际返回或保存的原图绝对路径",
  "prompt_sha256": "实际调用提示词UTF-8字节的SHA-256",
  "reference_sha256": {},
  "raw_sha256": "实际返回原图文件SHA-256"
}
```

有输入时 `reference_sha256` 以任务references中的原登记项为键、文件SHA-256为值；素材编辑源额外用 `edit:<assetId>` 为键。`tool_call_id`和`tool_model`仅在工具真实披露时添加。内部编号留在回执，不进入生图提示词。调用后不得改任务提示词来匹配结果；实际提示词若调整了，应先更新任务并重新自检，再调用工具。

```powershell
python <skill>/stages/21-concepts/scripts/run_generation.py <project> --stage content --import-result <receipt.json>
```

代表页用 `--stage concepts`，全篇用 `--stage full`。导入仍核对前序闸门、提示词、编辑源与上传许可，校验回执哈希并记录真实调用；它不发起生图，也不能独立认证回执真实性，代理必须如实取自当前调用记录。完整预览另按原图插入契约本地插图、实际查看后提交批准。

整页原图仍必须精确16:9，只允许等比缩放为1920×1080。比例不合格时保留原图和失败回执，按已有规则图生图修订，不能补边或裁切掩盖。每次失败调用也应导入真实返回图以记录次数；无返回图的失败在阶段日志记录实际调用编号和错误，不虚构成功回执。修改旧图使用新任务与GEN编号并保留编辑谱系，不用同一调用证明多张独立图片。

## 用户明确选择的外部通道

只有用户明确选择或确认CLI/API时才切换；内置工具不可用、普通质量／尺寸／保存路径控制及“批量”措辞均不自动触发回退。官方imagegen CLI遵守其skill回退指令，使用随附CLI，不自行改写其脚本；如需接入本工作流，用外层适配器转换参数与真实返回证据，不改上游脚本。其他供应商使用原CLI JSON适配契约，密钥仅经环境变量提供。

外部通道配置真实provider、模型ID、credentialEnv、适配脚本和上传许可，按既有流程自检后 `--execute`；账本必须记录实际模型与request_id。生图费用按该供应商定价说明。内置工具按当前账户额度与使用规则，不臆测价格或承诺无限额度。两种通道共用原图保真、事实边界、比例、逐页审阅和批准规则。
