# 阶段产物、完成条件与恢复契约

本文件保留详细阶段表，按标题选择当前阶段信息；不在入口一次性加载全文。

## 设计规范的统一入口

设计优先顺序、条件性手法与数值复看依据统一见[设计判断与检查提示](design-principles.md)。提示词约束见[生图提示词口径](../stages/13-design/references/gen-prompt-scope.md)；主文件只负责阶段编排，不重复完整设计条文。

## 工作流总览（0–7 步）

| 步骤 | 阶段 | 做什么 | 关键产物 | 停机点 |
|---|---|---|---|---|
| 0 | 0 | 建立环境：项目目录骨架、依赖与字体检查、材料登记入口 | `00_intake/`、`01_inventory/` 模板 | — |
| 1 | 1.1 | 遍历信息：读遍所有材料的文字与图片，询问 PPT 要求（是否需要目录页、**是否需要致谢页，默认不需要**、**是否需要演讲稿，默认不需要**、是否需要顶部进度条、AI 生图配置） | `00_intake/project-brief.md`、`01_inventory/materials.json`、`00_intake/ai-image-config.json` | ✅ 需求与材料确认 |
| 2 | 1.2 | 选内容：读完全部材料后，按 PPT 要求挑出上屏文字与图片（候选内容宁多勿缺，写材料原文的精炼版本；阶段 1.3 再精简为最终上屏文案），先完成 content-plan.md 的文案、原文索引和预留图片编号，再按三种设计方向各生成一组补充图片（每组封面大图＋内容页背景底图，有目录页时每组再多一张，致谢页复用背景底图，**全部横版**），将真实生成结果回填已先完成的 Markdown 内容清单 | `02_design/content-plan.md`、`02_design/image-intent-plan.json`、`02_design/generated-assets.json` | — |
| 3 | 1.3 | 设计：写一版 Markdown 设计稿——宏观结构＋三种设计风格＋阶段 1 的 PPT 要求；逐页写清归属、宏观版式、标题与说明意图，写下**最终上屏文字**，并按嵌套排版树分级（分块方式→各分块→分块上部／下部／左部／右部／分块内→并列文本逐条）写清文字关系、位置、具体文案与文段类型，以及图片与图形归属；文本框样式集中在风格要求，特殊分块在风格与分块说明分别交代并保留创意空间；写完停机等用户修改 | `02_design/design-spec.md`、`02_design/content.json`、`02_design/claim-map.json` | ✅ 设计稿复核 |
| 4 | 2.1 | 三版预览：按设计稿逐项详细描述分区、文本框与图形元素，让 AI 依据设计稿与详细元素提示词为三种风格各生成整页代表页预览，交用户选择用哪种风格 | `03_concepts/option-{a,b,c}/<Sxx>.png`、`03_concepts/option-{a,b,c}/preview.json` | ✅ 方案确认 |
| 5 | 2.2 | 全篇预览：把选定风格约束补进设计稿，再让 AI 依据设计稿、详细元素提示词与风格约束生成全部页面底稿，本地插入登记原图并应用计划边缘轮廓，逐页查看后交用户确认 | `04_full-preview/slides/`、`04_full-preview/previews.json`、`02_design/image-plan.json` | ✅ 预览批准 |
| 6 | 3.1–3.3 | 交付：先逐页生成非文字元素识别清单（`05_reconstruction/element-inventory.md`）→从已批准预览图里拆出元素→用 AI 抠图、裁切、SVG 重绘与 PPT 原生图形重建素材→组装成可编辑 PPTX→逐页渲染评审美观度，必要时自由调整元素位置并重新验收（`prepare_review.py` 生成预览/渲染逐页对照图与待审记录，`validate_project.py --mode release` 核对结构、文本与元素完整性；不再做自动逐像素比对） | `05_reconstruction/`、`06_build/deck-spec.json`、`07_delivery/deck.pptx` | 无讲稿时为终点；需要讲稿时继续阶段4 |
| 7 | 4（可选） | 演讲稿：阶段 1.1 确认需要时，为成品写逐页演讲备注与完整讲稿 | `08_speaker-notes/notes.json`、`08_speaker-notes/speaker-script.md` | — |

除停机点外必须连续执行：`0`、`1.2`、`3.1`–`3.3`、`4`（仅在用户要求讲稿时）以及每个阶段内部都不得中断任务进程（见规则 26）。

## 首次使用

先按[分步读取约定](context-loading.md)检索执行与工件章节，首次进入步骤补读适用规范，已读且版本未变的片段可复用。设计稿及提示词的每轮编写／修订前也须按版本复核相关规范片段，具体时点与范围统一见[三个必读时点](operations.md#三个必读时点)，脚本自检不替代阅读。再运行阶段 0 的初始化器。实际执行工具时按需读取[执行与验收约定](operations.md)。以下命令中的路径占位符须替换为实际绝对路径：

```powershell
python <skill-dir>/stages/00-init/scripts/init_project.py <project-dir>
```

阶段职责、图像术语、文字可编辑性与返工路由统一见[阶段边界表](artifact-contract.md#阶段边界与返工路由)。

同一图片位多轮比例修订仍无效时，允许[本地修正空白图框](preview-contract.md#多次修订后的本地空白图框修正)，保留原生成图与记录，修正后复看。

默认生图使用 `imagegen` skill 的内置 `image_gen` 工具；内置模式与外部接口的选择、配置和结果登记统一见[生图通道与结果登记](image-generation.md)。已有项目不静默切换通道。

## 阶段路由

| 步骤（阶段） | 子 skill | 必需产物 | 停止或完成条件 |
|---|---|---|---|
| 0（0） | [项目初始化](../stages/00-init/SKILL.md) | 标准目录和起始模板 | 项目初始化完成，依赖与字体清单已检查 |
| 1（1.1） | [材料与需求](../stages/11-intake/SKILL.md) | 完整需求说明和材料清单 | 目录页、致谢页、演讲稿与顶部进度条结论、关键资料和 AI 配置均确认 |
| 2（1.2） | [内容与素材清单](../stages/12-content/SKILL.md) | 按 PPT 要求从材料里选出文字与图片内容、生成补充图片（16:9 横版），并写成一个 Markdown 内容清单 | 三种设计方向（a/b/c）各备齐封面大图＋背景底图（有目录页时各再多一张；致谢页复用背景底图）、每张图片有说明、清单覆盖全部编号 |
| 3（1.3） | [设计稿](../stages/13-design/SKILL.md) | 逐页设计稿、文案、粗略图片意图与可选生成素材登记 | 导出 Markdown 设计稿并暂停，用户复核或修改结束后才完成 |
| 4（2.1） | [三版方案](../stages/21-concepts/SKILL.md) | 三种方向，每种 1–3 页按设计稿生成的 AI 整页预览与生图证据 | 每页 1920×1080、哈希与账本一致、`promptSummary` 已写，必须由用户选择或提出修改 |
| 5（2.2） | [完整预览](../stages/22-full-preview/SKILL.md) | 按确认风格由 AI 生成的整套 1920×1080 整页预览与生图证据、`image-plan.json` | 覆盖所有定稿页面、`styleConstraints` 已写、原图已本地插入且登记边缘轮廓已应用，逐页实际查看后等待用户确认 |
| 6（3.1） | [元素拆解](../stages/31-element-audit/SKILL.md) | 从已批准预览图逐页拆出的元素清单 | 所有可见元素均有记录 |
| 6（3.2） | [素材重建](../stages/32-asset-rebuild/SKILL.md) | AI 抠图、裁切结果、SVG 重绘、原生图形与位图素材 | 素材经过检查且来源可追溯 |
| 6（3.3） | [组装与验收](../stages/33-build/SKILL.md) | 可编辑 PPTX、渲染图、逐页对照图与质检报告 | 图片嵌回、逐页人工对照审阅并签署通过 |
| 7（4，可选） | [演讲稿](../stages/40-speaker-script/SKILL.md) | 逐页演讲备注与完整演讲稿 | 用户要求讲稿时逐页备注与讲稿覆盖全部页面；不需要时跳过本阶段，交付在 3.3 结束 |

## 中断恢复

检查 `workflow-state.json` 以及对应阶段的必需产物，从最早未完成或已失效的阶段继续。不能仅凭目录或文件存在判断完成；只有达到该阶段完成条件后，才更新状态。

使用 `shared/scripts/workflow.py <project-dir> status` 检查指纹（末尾一行会写明当前是否可以停在停机点），用 `stop-point` 做停机点自检，使用 `complete <阶段>` 保存验收版本；不要手填 `complete` 绕过检查。构建默认是 `draft`，仅正式 `release` 校验和逐页审阅通过后交付。旧版状态无指纹时重新验收，不自动认定完成。
